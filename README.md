# Telegram Shop Bot — магазин ссылок

Телеграм-бот: у каждого пользователя свой профиль с балансом, баланс пополняется
криптовалютой, с баланса покупаются товары (ссылки). Каталог показывает цену за
единицу и остаток на складе, после оплаты бот сразу выдаёт ссылки.

## Как это работает

1. Пользователь жмёт `/start` — создаётся профиль с нулевым балансом.
2. «💳 Пополнить баланс» → способ оплаты → сумма → счёт. Зачисление автоматическое.
3. «🛍 Каталог» → товар → выбор количества → «Купить». Деньги списываются с баланса,
   ссылки приходят в чат и остаются в «📦 Мои покупки».

Один товар = набор ссылок на складе. **Одна ссылка — одна единица товара**: доступное
к покупке количество считается автоматически, проданная ссылка никому больше не уйдёт.

## Быстрый старт

```bash
npm install
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_IDS
npm start
```

Проверка логики магазина (покупки, баланс, склад):

```bash
npm test
```

### Обязательные настройки в `.env`

| Переменная  | Что это |
|-------------|---------|
| `BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | Telegram ID админов через запятую (свой ID узнать у [@userinfobot](https://t.me/userinfobot)) |

Без `ADMIN_IDS` админка не откроется, товары добавить будет некому.

## Оплата

### Криптовалюта через @CryptoBot (основной способ)

1. Открыть [@CryptoBot](https://t.me/CryptoBot) → **Crypto Pay** → **Create App** → скопировать токен.
2. Положить его в `CRYPTO_PAY_TOKEN`, в `CRYPTO_PAY_ASSETS` перечислить принимаемые монеты.
3. Для мгновенного зачисления указать в настройках приложения вебхук:
   `https://ваш-домен/webhook/cryptobot` и задать `PUBLIC_URL` в `.env`.

Счёт выставляется в валюте магазина (по умолчанию рубли), пользователь платит любой
поддерживаемой криптой — курс считает CryptoBot. Подпись вебхука проверяется, повторные
уведомления не начисляют деньги дважды. Если вебхук не настроен, есть кнопка
«🔄 Я оплатил — проверить»: бот сам опросит статус счёта.

### Криптоперевод на свой кошелёк (ручное подтверждение)

`MANUAL_CRYPTO=1` и список кошельков в `MANUAL_CRYPTO_WALLETS` (`Название=Адрес;Название=Адрес`).
Пользователь переводит деньги и жмёт «Я оплатил», админам прилетает заявка с кнопками
«✅ Зачислить» / «❌ Отклонить».

### Карта и СБП

В меню оплаты уже стоят кнопки-заглушки «Скоро». Чтобы включить способ, нужно добавить
провайдера в `src/payments/` (по образцу `cryptobot.js`) и снять `available: false`
в `listMethods()` — остальной код (счета, зачисление, история) менять не придётся.

## Админка (кнопка «🛠 Админка» или `/admin`)

- **📦 Товары** — создать товар (`Название | цена | описание`), залить ссылки пачкой
  (по одной в строке), поменять цену/название/описание, скрыть или удалить товар.
- **💰 Заявки на пополнение** — подтверждение ручных криптопереводов.
- **👥 Пользователи** — поиск по ID или @username, начисление и списание баланса, блокировка.
- **📊 Статистика** — пользователи, заказы, выручка, пополнения, остаток ссылок.

О каждой продаже и заявке админам приходит уведомление в чат.

## Структура

```
src/
  index.js            запуск: HTTP-сервер + бот
  server.js           healthcheck и вебхук CryptoBot
  config.js           конфиг из .env
  bot/
    index.js          сборка бота, сессии, доступ, роутинг
    keyboards.js      меню
    prompts.js        пошаговый ввод текста
    notify.js         уведомления админам и пользователям
    handlers/         start, profile, catalog, topup, admin
  services/
    billing.js        баланс и журнал операций
    shop.js           покупка (списание + выдача ссылок в одной транзакции)
  payments/
    index.js          реестр способов оплаты
    cryptobot.js      Crypto Pay API
  db/                 SQLite-схема и репозитории
test/                 тесты магазина
```

Деньги везде хранятся целыми числами в копейках. Любое изменение баланса проходит
через `billing` и попадает в журнал `transactions`, покупка целиком идёт в одной
SQLite-транзакции — при гонке двух покупателей ссылка не продастся дважды.

## База данных

SQLite-файл по пути `DB_PATH` (по умолчанию `data/shop.db`), схема создаётся сама при
первом запуске. Файл базы в git не попадает — для бэкапа достаточно скопировать его
вместе с `-wal`/`-shm`.

## Деплой

`.github/workflows/deploy.yml` выкатывает `main` на сервер и перезапускает pm2.
На сервере нужно один раз:

```bash
cd /var/www/app
cp .env.example .env && nano .env   # токен, админы, ключи оплаты
npm install --production
pm2 start src/index.js --name app && pm2 save
```

Режим `BOT_MODE=webhook` (плюс `PUBLIC_URL` и `BOT_WEBHOOK_SECRET`) переводит бота с
long polling на вебхук `https://ваш-домен/webhook/telegram` — полезно, когда инстансов
несколько или нужен мгновенный отклик.
